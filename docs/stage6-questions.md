## 1. 물은 것

### Q1. 영어 문서 옆에 한국어 판을 둘까

README, CONTRIBUTING, SECURITY, CODE_OF_CONDUCT, 양식을 영어로 바꿀 때 한국어 판을 어디까지 둘지 물었다. 오픈소스는 보통 README.md를 영어로 쓰고, 번역은 README.ko.md처럼 따로 둔다. 기여 문서는 영어 하나인 곳이 많다.

- A. README만 두 벌로 둔다(README.ko.md).
- B. 영어만 둔다.
- C. 바깥 문서를 모두 두 벌로 둔다.

고른 답: A. 고칠 때 같은 PR에서 함께 고친다.

### Q2. 커밋, PR, 이슈의 언어

찾아보니 `.githooks/commit-msg`와 "PR 제목 검사"는 한국어를 요구하지 않는다. 형식, 50자, 마침표만 보고, 한국어인 것은 오류 메시지뿐이다.

- A. 이 세션의 PRD와 티켓부터 영어로 쓴다.
- B. 문서 영어화(레포 규칙 티켓)가 합쳐진 뒤부터 영어로 쓴다.
- C. 한국어로 둔다.

고른 답: B. 그래서 이 PRD와 티켓은 한국어다.

### Q3. 안쪽 문서와 코드 주석

세어 보니 패키지 코드에 한글 줄이 약 3,700, 테스트에 약 3,000, ADR 44개에 약 1,200, DESIGN.md가 약 2,000줄이다.

- A. 전부 영어로 바꾼다.
- B. 일할 때 읽는 것(AGENTS, GLOSSARY, DESIGN, 기획·구현 문서, 코드 주석, 테스트 이름)만 바꾼다. 지난 ADR과 문답 기록은 그대로 두고, 새 ADR부터 영어로 쓴다.
- C. 바깥 문서만 바꾼다.

고른 답: B. ADR은 다시 고치지 않는 기록이고, 파일 이름이 이미 영어다.

### Q4. 용어집의 영어 이름

코드가 이미 쓰는 영어 이름(`Work`, `Claim`, `MergeRun`, `Verdict`, `Presence`, `NearbyWork`, `Qa`)을 그대로 가져왔다. 걸리는 것은 넷이었다.

- 작업 = Work. 영어에서 셀 수 없는 말이라 "3 works"는 풀어 쓴다. Task는 용어집이 피하는 말이고, Workstream은 너무 길다.
- @호출 = @call. 한국어가 "멘션"을 피한 까닭(사람끼리의 멘션과 헷갈림)이 영어에도 그대로다.
- 부딪힘 = Conflict. 한국어는 "직접 충돌"과 헷갈려 따로 만든 말이지만, 영어는 Direct / Indirect를 붙이면 묶는 말로 자연스럽다(ADR-0041 파일 이름).
- 중요도의 참고 = FYI, 논의 = Discuss. 코드는 `reference`다.

고른 답: 표대로. 용어집의 각 용어 옆 괄호에 적었다.

### Q5. 웹 화면의 처음 언어

Discord와 Slack은 기기나 브라우저 언어를 따른다.

- A. 브라우저 언어를 따르고, 한국어나 영어가 아니면 영어로 띄운다.
- B. 늘 영어로 시작하고, 한국어는 설정에서 고른다.

고른 답: B. 고른 언어는 개인 설정으로 서버에 남긴다.

### Q6. 함께 보는 글의 언어

화면 글은 사람마다 다르게 보일 수 있지만, Omagari가 한 번 써 두고 모두가 보는 글이 있다. GitHub 라벨 이름(지금은 `직접 충돌`, `확인됨` …), 이슈와 결정 PR 본문, 훅과 러너가 에이전트에게 넣는 글, CLI 출력이다. 채널의 부딪힘 알림은 데이터로 저장되고 웹이 그린다. GitHub 봇(Dependabot, Renovate)과 git, gh CLI는 영어 하나다.

- A. 셋 다 영어 하나로 쓴다. 한국어 라벨은 서버가 이름을 바꾼다. 러너는 물은 말로 답한다.
- B. 워크스페이스 설정에 언어를 두고 따른다.

고른 답: A.

### Q7. 문체 기준

discord.com의 영어 글(2026-11-19 확인)은 짧고 친구에게 말하듯 쓴다("Hop in when you're free, no need to call"). 2인칭과 줄임말, sentence case를 쓰고, 농담은 길 잃은 화면("Wrong turn?") 같은 곳에만 한다. 한국어 도움말(support.discord.com)은 Cloudflare 확인 화면에 막혀 보지 못했다. 그래서 한국어 예는 우리 화면 글을 직접 고쳐 보였다.

| 지금                                       | 한국어                                  | 영어                                       |
| ------------------------------------------ | --------------------------------------- | ------------------------------------------ |
| 바꾸지 못했어요. 잠시 뒤 다시 시도해 주세요. | 못 바꿨어요. 조금 있다 다시 해 볼래요?  | Couldn't save that. Try again in a bit?    |
| (비어 있어요)                              | 아직 아무것도 없어요                    | Nothing here yet                           |
| 네트워크를 확인하고 다시 시도해 주세요.    | 연결이 끊긴 것 같아요. 인터넷을 확인해 볼래요? | Looks like you're offline. Check your connection? |

- A. 해요체 / 2인칭과 줄임말, 한 줄에 한 가지, 가벼운 말은 빈 화면·오류·안내에만, 팀 일은 담백하게.
- B. 더 가볍게(팀 일에도 가벼운 말, 반말도 섞기).
- C. 더 담백하게(가벼운 말 없이 짧고 또박또박).

고른 답: C. 해요체, 2인칭과 줄임말은 그대로 두고 농담만 뺀다. DESIGN.md에 "Writing" 칸으로 둔다(#302).

### Q8. 개인 설정에 무엇을 넣나

지금 설정 창은 "나 → 내 에이전트", "워크스페이스 → 부딪힘 알림, 라벨"이다. 브라우저 알림은 없고 새 글 점만 있다. 어두운 화면은 DESIGN.md에 색만 있다. Discord 사용자 설정에는 모양, 알림, 언어가 있고 서버 설정은 따로 연다. Slack은 환경설정(알림, 모양, 언어)이 개인 설정이다.

- A. 언어와 모양만 넣는다. 알림은 다음 단계로 미룬다.
- B. A에 브라우저 알림을 더한다.

고른 답: B.

### Q9. 브라우저 알림의 종류

사람끼리의 멘션은 아직 없어 뺐다. 나를 기다리는 일 셋으로 정했다.

| 종류                  | 기본                             |
| --------------------- | -------------------------------- |
| 내 작업의 부딪힘      | 중요도가 논의이면 켬, 참고이면 끔 |
| 내가 물은 것의 답     | 켬                               |
| 내가 낄 결정과 토론   | 켬                               |

규칙은 Slack과 Discord가 하는 대로다. 방해 금지이면 띄우지 않는다(지금도 "알림을 받지 않아요"라고 적혀 있다). 보고 있는 탭에는 띄우지 않는다. 권한은 설정에서 켤 때 묻는다.

고른 답: 이대로.

## 2. 스스로 답한 것

- **다국어 라이브러리**: 들이지 않는다. 언어마다 사전 하나(한국어는 영어와 같은 키의 타입)와 `Intl`이면 된다(구현 문서 10장). 웹 글은 한글 줄 약 1,300이다.
- **개인 설정을 어디에 두나**: 서버에 멤버마다 둔다. Slack과 Discord처럼 기기를 바꿔도 따라온다. 알림 권한만 브라우저마다 있다.
- **티켓을 어떻게 나누나**: 웹 글 옮기기는 넓은 고침이라 틀(#303)을 먼저 두고 화면 묶음 셋(#304~#306)으로 나눈다. 마지막 묶음이 한글 검사로 닫는다. 이모지·반응·GIF·프로필(#292~#295)은 마지막 묶음만 기다리게 해 새 글을 한 번에 옮긴다.
- **이 레포의 부딪힘 라벨**: 서버 티켓(#307)이 이름을 바꾼다. 레포 규칙 티켓(#300)은 건드리지 않는다.
- **README의 웹사이트 칸**: 문서 사이트가 없으니 비워 둔다.
