# 지표의 "들어온 멤버"는 웹에서 읽거나 쓴 멤버이고, 날은 서울의 자정으로 자른다

1단계를 다 만들었을 때 확인할 것은 "두세 명이 매일 들어온다"이다(구현 문서 1장의 단계 표, PRD #3). 그러려면 서버가 날마다 들어온 멤버 수와 문답 수를 세야 한다(이슈 #23). 문서는 "들어온", "하루", 셀 "문답"이 무엇인지 정하지 않았다.

- **들어온 멤버는 그날 웹에서 무언가를 읽거나 쓴 멤버다.** 웹이 실시간 연결을 열 때(웹을 열거나, 끊겼다 다시 붙을 때)와, 웹만 부르는 채널의 경로(지난 대화, DM 읽기, 글 쓰기, 묻기, 채널 만들기)를 부를 때 센다. Slack이 일간 활성 사용자를 "24시간 안에 글을 만들었거나 읽은 사용자"로 센 것을 따랐다([Slack S-1, 2019](https://www.sec.gov/Archives/edgar/data/1764925/000162828019004786/slacks-1.htm)).
  - **러너, CLI, 훅은 세지 않는다.** 러너는 켜 두면 사람이 없어도 붙어 있고, `omagari status`와 `omagari status set`은 스킬을 따라 에이전트가 부른다(ADR-0010). 이것을 세면 사람이 오지 않은 날에도 들어온 것으로 보인다.
  - **열어 둔 창이 붙어 있기만 한 것은 세지 않는다.** 자정을 넘겨 열어 둔 창은 다시 붙거나 채널에서 읽고 쓸 때 그날의 것으로 센다. Slack도 "연결되어 있던 시간"과 "실제로 쓴 시간"을 따로 셌다([Slack, Work is fueled by true engagement](https://slack.com/intl/en-ca/blog/news/work-is-fueled-by-true-engagement)). 2단계로 갈지 정하는 수라, 잊고 둔 창으로 부풀리기보다 덜 세는 쪽을 골랐다.
- **문답은 그날 서버가 받은 문답이다.** 공개 범위와 상관없이 DM과 `@호출`을 모두 센다(용어집: 문답은 질문과 답 한 쌍이고 공개 범위는 문답마다 붙는다). DM을 채널에 올리는 것은 새 문답이 아니라 그 문답의 공개 범위가 바뀌는 것이라 다시 세지 않는다. 물은 시각으로 세고, 답하지 못한 문답(끊긴 답 포함)도 사람이 물은 것이라 센다. 러너가 꺼져 있어 받지 않은 질문은 문답이 생기지 않아 세지 않는다. 터미널의 `omagari runner ask`는 서버를 거치지 않아 세지 않는다.
- **날은 Asia/Seoul의 자정으로 자른다.** 만드는 팀의 하루다. 서버는 어디서 돌든(대개 UTC) 이 시간대로 자른다. 서울은 일광 절약 시간이 없어 하루가 늘 24시간이다.
- **지표는 수만 담는다.** 서버가 지표를 위해 따로 남기는 것은 날마다 들어온 멤버(`visits`: 날짜와 로그인)뿐이다. 문답 수는 이미 있는 문답 기록에서 물은 시각만 읽어 센다. `api.metrics`와 `omagari metrics`는 날짜와 두 수만 내고, 누가 들어왔는지와 무엇을 물었는지는 내지 않는다.

## Considered Options

- **세션을 든 요청 모두를 세기**: 한 곳(인증 미들웨어)에서 끝나지만, 에이전트가 부르는 CLI와 상태 한 줄 쓰기까지 세어 사람이 오지 않은 날도 들어온 날이 된다.
- **웹이 붙어 있던 날을 모두 세기(접속 상태와 같은 기준, #39)**: 접속 상태의 "온라인"과 맞지만, 잊고 열어 둔 창 하나로 날마다 들어온 것이 된다. 접속 상태는 지금을 보이는 것이고 지표는 머물렀는지를 재는 것이라 기준을 달리했다.
- **UTC나 서버 기기의 시간대로 자르기**: 서울의 오전 9시가 날의 경계가 되어 하루의 일이 두 날로 나뉜다.
- **문답 수도 지표 표에 따로 적기**: 문답 기록이 지워져도 수가 남지만, 지금은 문답을 지우는 일이 없어 같은 것을 두 번 적게 된다.

## Consequences

- 들어온 멤버의 날짜는 적을 때 정해진다. 시간대를 바꾸면 그 뒤에 적는 것만 바뀐다. 문답 수는 읽을 때 자르므로 지난 것까지 바뀐다.
- 브라우저 탭을 연 것만으로는 눈으로 봤는지 알 수 없다. 웹을 열거나 다시 붙은 것은 들어온 것으로 센다. 더 정확해야 하면 웹이 창이 보이는지(`visibilitychange`)를 알려 그때만 센다.
- 문답 기록을 지우거나 줄이는 일이 생기면, 그 전에 문답 수를 날마다 따로 적어 둔다.
- 날마다 몇 명인지만 나온다. 같은 두세 명이 매일 오는지(잔존)를 보려면 `visits`에서 로그인을 읽어야 한다. 필요해지면 API에 더한다.
