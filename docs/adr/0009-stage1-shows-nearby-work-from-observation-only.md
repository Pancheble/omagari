# 1단계는 관측과 상태 한 줄만으로 근처 작업을 보여 준다

Room은 범위 선언, 선점, 긴급도가 붙은 편지함, 막고 기다리기를 한 묶음으로 처음부터 둔다. Omagari의 1단계는 관측(바뀐 파일과 그 내용)과 상태 한 줄만 세션 시작 훅과 편집 전 훅에 싣고, 선점, 편지함과 피드, 묻고 기다리기(`omagari ask`), 정의 줄은 2단계에 부딪힘 알림과 함께 넣는다. 1단계는 "공간에 머무는가"를 재는 단계이고(구현 1장), 편지함에 넣을 알림이 아직 없으며, 정의 줄은 언어마다 파서를 붙여야 해서 러너에 몰린 불확실성을 더 늘리기 때문이다.

`omagari ask`는 상대의 에이전트를 상대의 사용량으로 부른다. "에이전트는 주인만 부를 수 있다"(구현 1장)와 어긋나므로, 받는 쪽이 비용에 동의하는 방식을 먼저 정해야 한다. 미정이다.

## Consequences

- 1단계의 편집 전 훅은 "누가 이 파일의 어디를 바꾸는 중"까지만 말한다. "여기 내가 할 것이다"라는 의도는 상태 한 줄로만 보인다.
- ADR-0008의 선점은 2단계부터 쓰인다.
