# 도그푸딩 서버는 Fly.io에서 `dev`를 따라 저절로 배포된다

ADR-0019는 서버와 멤버가 `main`을 쓰게 했고, ADR-0022는 @Pancheble이 기능이 갖춰졌다고 할 때만 릴리즈하게 했다. 5단계는 서버를 올리고 Omagari로 Omagari를 만들며 써 보는 단계인데, 서버가 `main`을 따르면 허브가 하루에 여러 번 `dev`에 머지하는 것을 다음 릴리즈까지 써 볼 수 없다. 5단계 그릴링에서 아래를 정했다(2026-11-17 @Pancheble, `docs/stage5-questions.md` Q3, Q5, Q6).

- **어디에**: Fly.io. 늘 켜진 작은 기계 하나와 SQLite를 둘 디스크(볼륨), `*.fly.dev`의 HTTPS 주소를 쓴다. 디스크의 날마다 스냅샷이 백업이다. 한 달 약 4~6달러다.
- **어느 판을**: 도그푸딩 서버는 `dev`를 따른다. `dev`에 머지되고 CI가 통과하면 GitHub Actions가 Fly.io에 배포한다. Fly는 건강 확인을 통과한 판만 갈아 끼운다. @Pancheble의 러너, CLI, 훅도 `dev`를 받은 클론에서 돈다.
- **러너는 스스로 받는다**: 서버의 계약이 더 새로워 거절당하면, 러너가 자기가 깔린 클론에서 `git pull --ff-only`와 `npm ci`를 하고 스스로 다시 켠다. 관측하는 레포 폴더는 건드리지 않는다. 깔린 클론에 고친 파일이 있거나 빨리 감기가 안 되면 아무것도 하지 않고 지금처럼 알리기만 한다. 훅도 같은 클론의 파일을 쓰므로 함께 새 판이 된다. 받아 오는 코드는 서버가 아니라 GitHub의 그 클론의 브랜치에서 오므로, 손으로 받는 것보다 위험하지 않다(Q6).
- **`main`은 그대로**: 릴리즈한 판이고, 나중에 다른 사람이 쓸 때 받는 곳이다. 릴리즈하는 때는 ADR-0022 그대로다.

## Considered Options

- **VPS(Hetzner, AWS Lightsail)**: 조금 싸거나 같지만 HTTPS, 패치, 배포 스크립트를 직접 챙긴다. 1인 개발이라 서버를 관리하는 시간이 가장 비싸다.
- **내 Mac과 Cloudflare Tunnel**: 무료지만 Mac이 잠들면 멈추고, 하위 세션의 테스트로 이미 부하가 크다.
- **AWS App Runner, Fargate**: App Runner는 오래 붙는 WebSocket을 권하지 않고 지워지지 않는 디스크가 없다. Fargate는 WebSocket에 로드 밸런서가 필요하고 디스크가 네트워크 파일 시스템이라 SQLite의 잠금이 깨질 수 있다.
- **서버는 `main`, 써 보고 싶으면 릴리즈**: ADR-0022와 부딪힌다.
- **`dev`에서 손으로 누를 때만 배포**: 머지할 때마다 사람이 눌러야 한다.
- **러너는 알리기만 하고 사람이 받는다**(`omagari update` 명령 하나로 줄이기): 받을 때까지 러너가 멈춰 있다.
- **서버가 앞 판 몇 개의 계약을 받아 준다**(Room): ADR-0019에서 멤버가 몇뿐이라 다 같이 올리는 편이 싸다며 버렸다.

## Consequences

- 서버가 웹 화면도 낸다. 지금은 개발용 Vite로만 뜬다.
- 계약 버전은 4단계 이틀 동안 32에서 42로 열 번 올랐다. 러너가 스스로 받지 않으면 그때마다 하위 세션들이 Omagari 없이 돈다.
- 배포된 DB가 생겨, 스키마를 바꾸는 PR은 이미 있는 DB에서도 서버가 켜져야 한다. 지금처럼 켤 때 빠진 칸을 더하는 방식을 그대로 쓴다.
- ADR-0019의 "서버는 `main`으로 띄운다"를 도그푸딩 서버에 한해 바꾼다. 다른 팀이 직접 띄우는 서버는 여전히 `main`이다.
