# 검사 명령은 레포에 커밋한 파일에서 읽고, 합쳐 돌려 보기는 기본으로 켜져 있다

Room은 합쳐 보기를 부르는 에이전트가 매번 명령을 준다. Omagari는 저절로 돌리므로(ADR-0036) 정해 둔 명령이 필요하다. 검사 명령은 레포에 커밋한 설정 파일 하나에 두고, 러너는 기본 브랜치에 머지된 판만 읽는다. 파일이 있으면 멤버의 러너는 따로 켜지 않아도 돌린다(2026-11-13 주인 확인, `docs/stage3-questions.md` Q2·Q6).

- 파일에는 검사 명령과, 선택으로 그 앞에 한 번 돌릴 준비 명령을 둔다. 파일의 이름과 꼴은 만들 때 정한다. 시안에서는 `.omagari.json`의 `check`와 `setup`으로 그렸다.
- 기본 브랜치의 판만 읽는다. 내 작업 폴더나 상대의 바뀐 파일에 든 판은 읽지 않는다. 서버는 명령을 주지 않는다(ADR-0033).
- 파일이 없으면 돌리지 않는다. 팀이 파일을 머지하는 것이 켜는 일이다.
- 러너를 켤 때 검사 명령과 "샌드박스 안에서 돈다"를 알린다. 명령이 바뀌면 다음에 켤 때 다시 알린다. 공유 수준을 알리는 것과 같은 자리다(ADR-0007).
- 끄는 것은 러너에서 한다. 공유 수준처럼 그 레포에 남는다. 웹은 켜졌는지만 보인다. 서버가 켤 수 없게 하려는 것이다.

## Considered Options

- **러너를 켤 때 주인이 준다**: 온전히 내 기기에서 정하지만 멤버마다 넣어야 한다. 두세 명 팀에서 각자 넣게 하면 아무도 안 넣는다(ADR-0024와 같은 까닭).
- **자동으로 찾는다**(`package.json`의 `test`): 설정할 것이 없지만 Node 레포에서만 된다. 널리 쓰는 "검사 명령" 설정 관례는 찾지 못했다. 가장 가까운 것은 Heroku CI의 `app.json`이다.
- **명령마다 한 번 허락받는다**(direnv 방식): 처음 보거나 바뀐 명령은 주인이 허락할 때까지 돌리지 않는다. 명령도 샌드박스 안에서 돌아(ADR-0033) 더 막아 주는 것이 적고, 기본이 꺼짐이 된다.

## Consequences

- 명령의 글자는 기본 브랜치에서 오지만, 명령이 실제로 돌리는 것은 합친 폴더의 스크립트와 테스트 파일이다. 상대의 변경이 거기 들어 있으면 그대로 실행된다. 안전은 이 결정이 아니라 샌드박스가 맡는다(ADR-0033).
- 검사 명령이 레포에 머지되면 멤버의 기기가 그때부터 저절로 명령을 돌린다. 켤 때의 알림과 끄는 스위치가 동의의 자리다.
- 기본 브랜치의 파일을 바꿀 수 있는 사람은 모든 멤버의 기기에서 돌 명령을 바꿀 수 있다. 워크스페이스의 멤버는 push 권한이 있는 사람이다(ADR-0011).
