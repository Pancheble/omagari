# 선점은 심볼·줄 범위·폴더에 걸고, 늘 걸며, 겹쳐도 거절하지 않는다

ADR-0004를 대체한다. 파일 내용이 서버에 올라오므로(ADR-0007) 선점의 단위와 줄 번호 옮기기는 Room을 따른다. 겹칠 때와 걸 때의 규칙은 우리 것을 둔다.

- **단위(Room과 같음)**: 심볼(정의 이름으로 줄 범위를 찾는다), 줄 범위, 폴더. 새로 만든 파일은 파일 전체.
- **줄 번호 옮기기(Room과 같음)**: 선점한 사람의 판과 내 판의 줄 차이를 계산해 내 사본의 줄 번호로 보여 준다. 상대의 내용을 읽을 수 없으면(공유 수준, 빠진 파일) 상대의 번호를 그대로 쓰고 "대략"이라고 표시한다.
- **겹쳐도 거절하지 않는다(우리 원칙)**: Room은 남의 선언 범위를 덮는 폴더 선점을 거절한다. 우리는 받아 주고 양쪽 편지함에 알린다(원칙 4·6).
- **늘 건다(Room과 다름)**: Room은 근처에 아무도 없으면 "필요 없다"며 걸지 않는다. 우리는 작업을 시작할 때 고칠 곳을 늘 선점한다. 편집마다 거는 것은 아니다.

## 왜 늘 거나

Room에서 "근처"는 다른 참가자의 선언 범위, 선점, 바뀐 파일이 내 경로와 겹치는 것이다. 앞사람이 혼자 일해 선점을 걸지 않았을 때, 나중에 온 사람이 보는 것은 다음뿐이다.

- 앞사람이 **이미 바꾼 파일**. 편집 전 훅이 "X가 이 파일을 바꿨다, 고치기 전에 선점하라"고 넣고, 내용은 읽기 도구로 본다.
- 두 사람이 **동시에 접속해 있으면**, 앞사람의 에이전트가 "누가 와 있다"를 보고 그제야 범위를 선언한다(지침이 그렇게 시킨다).
- 지금 접속한 사람이 아무도 없으면, 편집 전 훅은 오프라인인 사람의 선점과 변경을 넣지 않는다. 실제로 줄이 부딪힐 때의 알림과 합쳐 보기에 맡긴다.

즉 Room은 앞사람이 바꾼 것은 보여 주지만, 앞사람의 의도와 아직 손대지 않은 계획은 둘이 동시에 접속해 있을 때만 드러난다. 우리에게는 두 가지 이유로 모자란다.

1. 서로 다른 시간에 일하는 팀이 기본 경로다(구현 7장). 앞사람이 떠난 뒤에 온 사람에게는 "근처에 누가 있다"는 계기가 오지 않는다.
2. 바꿀 계약은 선점에 붙여 선언한다(구현 4장). 그런데 그 계약을 쓰는 사람은 다른 파일에서 일하므로 경로로는 근처가 아니다. 근처일 때만 걸면 선언도 걸리지 않고, 쓰는 사람은 코드가 바뀐 뒤에야 관측으로 안다. 우리 문서는 코드를 쓰기 전에 알리려 한다(구현 4장 "계획을 세울 때").

## Consequences

- 겹치지 않는 선점은 피드에만 남고 아무도 깨우지 않는다(Room도 선점 소식은 피드에만 둔다). 늘 걸어도 남이 받는 알림은 늘지 않는다.
- 비용은 작업을 시작할 때 에이전트가 하는 호출 몇 번이다. Room은 이런 비용 때문에 "겹칠 때만 조율"로 바꿨다(Room 결정 기록, 0.9.0). 선점이 쓰이지 않는데 호출만 는다면 다시 본다.
