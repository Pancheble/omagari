# 부딪힘은 러너가 자기 작업을 기준으로 계산하고, 서버는 묶어서 알린다

구현 2장은 서버가 "규칙 계산"을 한다고 적었고, 13장은 직접 충돌의 3-way 합치기를 서버와 러너 중 어디서 계산할지를 미정으로 남겼다. 러너가 계산한다. 각 러너는 자기 작업과 남의 작업이 함께 바꾼 파일을, 두 작업의 갈림점에 있던 판을 조상으로 `git merge-file`로 합쳐 보고, 정의 줄이 바뀐 심볼을 자기 사본의 심볼 색인에서 찾는다. 결과는 서버에 올리고, 서버는 두 작업 한 쌍과 종류마다 알림 하나로 묶어 채널과 편지함에 보낸다.

서버에는 레포가 없어 기준 커밋의 판도, 두 작업의 갈림점도, 바뀌지 않은 파일도 모른다. 러너는 레포를 들고 있고, 1단계의 근처 작업도 이미 자기 Git으로 남의 바뀐 줄을 계산한다. Room도 부딪힘을 서버가 아니라 각자의 기기에서 계산한다(`docs/room-behavior.md`).

## Considered Options

- **서버가 계산**: 러너가 바뀐 파일마다 기준 커밋의 판도 올리고 서버가 합친다. 계산이 한곳에 모이지만, 갈림점과 심볼 색인을 위해 서버가 레포를 받아 들고 있어야 하고, 공유 수준이 full이 아닌 사람의 작업은 서버가 볼 수 없다.

## Consequences

- 같은 쌍을 양쪽 러너가 따로 계산한다. 서버는 한 쌍의 결과를 하나로 묶고, 한쪽 러너가 꺼져 있어도 다른 쪽의 결과로 알린다.
- 내가 읽을 수 없는 남의 내용(공유 수준, 빠진 파일, 내 기기에 없는 기준 커밋)은 "부딪힐 수 있음"으로만 알린다.
- 서버의 "규칙 계산"은 묶기, 알릴 곳 고르기, 상태 한 줄의 표시처럼 서버가 가진 것만으로 되는 규칙에 한한다.
