# 부딪힘은 사람이 아니라 작업 사이에서 본다

기획 6장은 "한 사람의 에이전트끼리 부딪히는 것은 다루지 않는다. 그건 각자의 워크플로가 맡는다"고 적었고, 러너의 직접 충돌 계산, 근처 작업, 세션 시작 훅은 로그인이 나와 같은 작업을 건너뛰었다. 그런데 Omagari를 만드는 일 자체가 한 사람이 허브 세션과 이슈마다의 하위 세션 여럿을 서로 다른 브랜치에서 돌리는 모습이고, 4단계에서 #216과 #217이 같은 계약과 서버 파일을 고쳐 다시 합쳐야 했다. 5단계 그릴링에서 같은 사람의 작업끼리도 남처럼 보기로 했다(2026-11-17 @Pancheble: "원래 그걸 노린거 아닌가? 한 사람이 여러 에이전트를 굴리는데 그 에이전트끼리 겹치잖아", `docs/stage5-questions.md` Q1).

- 브랜치가 다르면 같은 사람의 작업도 직접 충돌, 간접 충돌, 중복 구현, 근처 작업, 두 훅, 알림과 포스트를 다른 사람의 작업과 똑같이 받는다. 같은 작업(같은 사람, 같은 브랜치)만 건너뛴다.
- 토론도 똑같이 열린다. 양쪽 모두 그 브랜치에서 쓰던 작업 세션을 갈라 띄워 서로 다른 맥락으로 입장을 낸다(ADR-0040). 두 쪽이 다 한 사람의 사용량으로 돈다.
- 묻기는 그대로 자기 에이전트에게 하지 않는다. 같은 기기라 다른 워크트리를 직접 읽을 수 있다. 대행도 주인이 늘 있으니 해당하지 않는다.

## Considered Options

- **다른 사람끼리만 보고 도그푸딩에 사람을 데려온다**: 데려올 사람이 있어야 시작되고, 혼자 에이전트 여럿을 돌리는 가장 흔한 쓰임새를 놓친다.
- **설정으로 켜고 기본은 끈다**: 끈 채로 쓰는 사람에게는 지금과 같아 값이 없다.
