# 관측은 바뀐 파일의 내용을 서버에 올린다

ADR-0001을 대체한다. Room처럼 관측이 바뀐 파일의 내용을 서버에 올리고, 공유 수준 셋을 그대로 가져온다. 기본은 full이다. 채널의 멤버는 같은 레포의 협업자라 서로에게 코드를 숨겨서 얻는 것이 작고, 파일 단위로만 겹침을 보면 같은 파일의 다른 곳을 고치는 두 사람에게도 알림이 가서 자주 틀리기 때문이다.

| 공유 수준 | 서버에 올라가는 것 |
| --- | --- |
| full(기본) | 바뀐 파일의 내용 전체 |
| declared | 바뀐 파일의 경로는 모두, 내용은 선점한 경로 안의 것만 |
| intent | 상태 한 줄, 선점, 계획만. 파일 내용은 없다 |

공유 수준은 주인이 러너마다 고르고, 처음 연결할 때 무엇이 나가는지 알린다. ADR-0001에서 늘 빼던 것은 그대로 뺀다: gitignore된 파일, 추적되더라도 `.env`와 `.env.*`(`.env.example`은 남긴다). 바이너리와 크기 상한을 넘는 파일은 경로만 보낸다. 상한은 Room의 값(파일 하나 512KiB, 합계 8MiB)에서 시작한다.

## Consequences

- 직접 충돌을 줄 단위로 가린다. 두 사람이 바꾼 같은 파일을 기준 커밋에서 3-way로 합쳐 보고, 줄이 실제로 부딪힐 때만 알린다(Room과 같은 방식).
- 선점한 사람의 줄 번호를 내 사본으로 옮길 수 있어, 선점을 심볼과 줄 범위로 건다(ADR-0008).
- 합쳐 돌려 보기가 푸시하지 않은 작업에도 된다. 러너가 기준 커밋(원격에 있어 누구나 받을 수 있다, ADR-0002) 위에 상대의 바뀐 파일을 얹고 자기 작업과 합친다. 상대가 full이 아니거나 빠진 파일이 있으면 그 부분은 합치지 못한다.
- 서버가 팀의 작업 중 코드를 들고 있다. 서버가 뚫리면 그 코드가 샌다. 그래서 워크스페이스에는 그 레포의 협업자만 들어와야 한다.
- 푸시하지 않은 작업을 합쳐 돌려 보면 서버에서 받은 코드를 러너 기기에서 실행하게 된다. 푸시된 브랜치는 GitHub에서 받지만 이 코드는 서버를 거친다. 이때의 안전장치는 미정이었고(구현 13장), 샌드박스 안에서만 돌리기로 정했다(ADR-0033).
- "선언한 범위"는 Room에서 범위 선언(scope)의 경로인데, 우리에게는 그 장치가 없어 선점한 경로로 읽는다.
