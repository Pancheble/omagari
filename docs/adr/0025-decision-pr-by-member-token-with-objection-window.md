# 결정 PR은 정리한 멤버의 이름으로 열고, 이의 창이 닫히면 Omagari가 머지한다

구현 2장은 GitHub 앱이 결정 PR을 만들고 머지한다고 적었고, 8장은 이의 창이 닫힐 때까지 이의가 없으면 Omagari 봇이 머지한다고 적었다. 창의 기본 길이는 13장의 미정이었다. 2단계에서는 GitHub 앱을 만들지 않는다. 서버는 로그인 때 멤버마다 `repo` 범위 토큰을 이미 받아 들고 있어서, 결정을 정리한 멤버의 토큰으로 브랜치, 커밋, PR을 만든다. 정리한 사람이 창의 길이를 "바로"나 "하루"로 고르고, 기본은 하루다. 창이 닫힐 때 이의가 없고 GitHub 규칙상 머지할 수 있으면 Omagari가 같은 토큰으로 머지한다(2026-11-12 주인 확인, `docs/stage2-questions.md` Q4·Q5).

## Considered Options

- **GitHub 앱**: PR이 봇 이름으로 열리고 멤버의 토큰에 기대지 않는다. 앱을 새로 등록해 레포에 깔고 서버가 앱 키를 들어야 한다. Omagari를 쓰지 않는 팀원에게 GitHub로 알려야 할 때 만든다.
- **이의 창 없이 사람이 머지**: 만들 것이 적지만, "관문 대신 이의 창"(원칙 4)이 결정 PR의 쓸모라 넣었다.

## Consequences

- 결정 PR과 머지가 정리한 멤버의 이름으로 남는다. 그 멤버가 레포 권한을 잃거나 토큰이 무효가 되면 열린 창의 머지가 멈추고, 그 사실을 대화에 알린다.
- 팀이 리뷰 필수로 설정했다면 그 규칙대로 사람의 승인을 기다린다(구현 8장). Omagari는 예외를 요구하지 않는다. 자기가 연 PR은 스스로 승인할 수 없으므로, 리뷰 필수 레포에서는 다른 멤버의 승인이 있어야 머지된다.
- 이의는 공간에서 내거나 GitHub의 변경 요청 리뷰로 낸다. 하나라도 걸려 있으면 머지하지 않는다. 이의가 모두 거둬지면 창이 처음부터 다시 열린다. 정리한 사람은 결정을 고쳐 같은 PR에 다시 올릴 수 있고, 결정을 버리면 PR을 닫는다(문답 Q11). 출처와 지난 이의가 한 PR에 남는다.
