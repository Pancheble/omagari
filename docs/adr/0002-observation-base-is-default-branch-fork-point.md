# 관측은 기본 브랜치와 갈라진 지점에 견준다

Room은 HEAD의 조상 가운데 원격 추적 브랜치에 있는 가장 새 커밋을 기준으로 삼는다. 그래서 푸시한 커밋은 관측에서 빠지고, 푸시된 작업은 열린 PR로 따로 보인다. Omagari는 그 브랜치와 기본 브랜치(원격 추적 ref)의 갈림점(merge-base)을 기준 커밋으로 삼아, 푸시 여부와 상관없이 그 브랜치가 기본 브랜치에 가져올 변경 전체를 관측한다. 부딪힘은 머지 순간에 드러나고(기획 2장), 직접 충돌의 단위가 "진행 중인 브랜치"이기 때문이다(구현 6장). 기획 문서에 기준이 적혀 있지 않아 새로 정했다.

## Considered Options

- Room 방식: 푸시한 뒤에는 관측에서 빠지므로 초안 PR을 늘 따로 읽어야 하고, 같은 작업이 두 곳에서 보인다.
- 갈림점 방식(고름): 관측 하나로 작업 전체가 보인다.

## Consequences

- 다른 기능 브랜치 위에 쌓은 브랜치는 밑 브랜치의 변경까지 내 것으로 보인다.
- 기본 브랜치를 오래 fetch하지 않아도 갈림점은 그대로라, 남이 이미 머지한 변경이 내 것으로 섞이지는 않는다.
