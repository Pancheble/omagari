# 합쳐 돌려 보기는 간접 충돌(추정)이 걸린 쌍을 잠잠해지면 저절로 돌린다

언제, 어느 쌍을, 누가 돌리는지를 정한다(2026-11-13 주인 확인, `docs/stage3-questions.md` Q7·Q8, A2·A3·A6).

- **어느 쌍**: 간접 충돌(추정) 알림이 선 쌍만 돌린다(구현 6장). 직접 충돌이 걸린 쌍은 합쳐지지 않아 돌리지 못한다. 중복 구현은 합쳐도 깨지는 일이 아니다. 선언된 계약 변경은 아직 바뀐 코드가 없다.
- **누가**: 그 추정을 계산한 러너, 곧 바뀐 정의를 쓰는 쪽의 러너가 자기 기기에서 돌린다(ADR-0023). 상대 러너가 꺼져 있어도 서버에 남은 관측으로 돌린다. 같은 내용의 판정이 이미 서버에 있으면 다시 돌리지 않는다.
- **언제**: 두 작업의 내용이 모두 2분 동안 바뀌지 않으면 돌린다. 커밋하지 않은 것도 합친다. 러너는 한 번에 하나만 돌린다. 도는 중에 내용이 바뀌면 그 판정은 지난 결과로 두고, 잠잠해지면 다시 돌린다. 2분은 시작 값이고 써 보고 고친다.
- **저절로만**: 사람의 버튼도, 에이전트의 명령도 두지 않는다. 서버가 러너에게 "돌려라"를 시키는 길을 만들지 않는다(ADR-0033).

## Considered Options

- **커밋할 때만 돌린다**: Crystal의 방식이다. 커밋한 것만 합쳐, 고치다 버릴 코드의 오탐을 줄인다. 에이전트는 끝날 때까지 커밋하지 않는 일이 많아 늦게 알게 되고, 상대의 커밋된 판을 따로 올리도록 관측의 계약을 바꿔야 한다. 고치는 중인 코드의 오탐은 따로 돌려 가린다(ADR-0035).
- **지켜보는 쌍을 모두 돌린다**: Crystal은 지켜보는 저장소마다 돌린다. 정의 줄이 바뀌지 않은 깨짐도 잡지만, 멤버의 기기에서 도는 것이라 비싸다. 구현 6장이 추정이 걸린 쌍만으로 정했다.
- **포스트의 "다시 돌려 보기" 버튼**: 서버가 러너에게 요청을 보내는 길이 생긴다.
- **에이전트의 명령으로 돌린다**: Room의 방식이다. 에이전트가 일을 끝내기 전에 부른다. 기기 안에서만 불러 안전하지만, 알림이 없는 쌍의 판정을 어디에 올릴지 새로 정해야 한다. 4단계의 실험(구현 7장)에서 함께 넣는다.

## Consequences

- 추정이 서지 않는 깨짐은 돌려 보지 않는다. 정의 줄이 바뀌지 않은 깨짐과, 정의 줄을 뽑지 못하는 언어(TypeScript 계열 밖, ADR-0026)의 레포가 그렇다.
- 바뀐 정의를 쓰는 쪽의 러너가 꺼져 있으면 추정도, 합쳐 돌려 보기도 없다.
- 멤버의 기기가 검사 명령을 저절로 돌린다. 끄는 것은 러너에서 한다(ADR-0034).
- 구현 6장의 "푸시된 브랜치끼리 합치는 길"은 따로 만들지 않는다. 푸시된 작업도 관측에 올라와 있어 같은 길로 합친다. 러너가 없는 팀원의 브랜치는 관측도 추정도 없어 돌리지 않는다.
