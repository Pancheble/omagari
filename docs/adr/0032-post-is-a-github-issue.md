# 포스트 하나가 GitHub 이슈 하나다

ADR-0027은 알림 하나를 부딪힘 포럼의 포스트 하나로 올렸고, 포스트는 Omagari 안에만 있었다. 2026-11-13 캔버스 검수에서 주인이 포스트를 GitHub 이슈와 맞추기로 정했다(이슈 #118). 포스트에서 한 말은 이슈 댓글로 가고, GitHub에서 단 댓글은 포스트 대화로 들어온다. 포럼의 거르기 태그는 이슈 라벨이고, 카드의 제목은 이슈 제목과 번호다. AI를 불러 한 말은 그 사람 계정으로 올리고 AI가 썼다고 표시한다.

만들면서 고른 세부는 아래와 같다. 주인이 PR #118에서 보고 바꿀 수 있다.

- **누구 토큰으로 여나**: 알림이 서면 Omagari가 이슈를 연다. 2단계에는 GitHub 앱이 없으므로(ADR-0025) 멤버의 `repo` 토큰을 쓴다. 알림의 두 사람 가운데 세션이 있는 사람의 것, 둘 다 없으면 아무 멤버의 것이다. 이슈는 그 사람 이름으로 열린다.
- **제목, 본문, 라벨**: 제목은 부딪힌 파일(또는 심볼)과 종류("pay.ts 직접 충돌")이고 사람은 넣지 않는다. 본문은 두 작업, 곳, 포스트 링크다. 종류 이름("직접 충돌", "간접 충돌", "중복 구현", "계약 변경")을 라벨로 단다. 그 뒤로는 GitHub이 원본이다. 사람이 GitHub에서 제목이나 라벨을 바꾸면 다음 주기에 포럼이 따라간다.
- **글 → 댓글**: 포스트의 글과 공개된 문답을 쓴 사람(문답은 올린 사람)의 토큰으로 댓글로 단다. 쓴 사람의 세션이 없으면 들어올 때까지 둔다. 결정 PR 줄은 올리지 않는다. 결정 PR이 이미 GitHub에 있다.
- **AI가 쓴 글**: 문답 댓글은 올린 사람의 글 뒤에 `> [!NOTE]` 인용으로 "🤖 **AI가 쓴 답** · 김지은의 Claude Code (모델 · effort)"와 물음을 적고 답을 붙인다. 앱에서는 문답 줄과 카드에 "AI" 배지를 단다(DESIGN.md "AI가 쓴 글").
- **댓글 → 글**: 주기(`followMs`, 기본 1분)마다 이슈의 댓글을 읽고 모르는 것을 포스트의 글로 들인다. 쓴 사람은 GitHub 로그인이라 멤버가 아닐 수 있다. 들어온 글에는 "GitHub" 표시가 붙는다. Omagari가 올린 댓글은 번호를 알아 다시 들이지 않는다. GitHub에서 고치거나 지운 댓글은 따라가지 않는다.
- **이슈 닫기와 풀림**: 알림이 풀리면 Omagari가 이슈를 한 번 닫는다(끝남). 사람이 GitHub에서 이슈를 닫아도 포스트는 풀림이 된다. 이슈가 다시 열리면 알림이 풀리지 않은 한 열림으로 돌아온다. Omagari가 닫은 뒤 사람이 다시 연 이슈는 다시 닫지 않는다. 알림은 코드에서 계산하므로 이슈를 닫아도 알림 자체는 풀리지 않는다(알림 카드의 "풀렸어요"는 알림의 것이다).
- **언제 맞추나**: 포스트에 글이 서거나, 문답이 올라오거나 답이 오거나, 알림이 서면 그 포스트를 곧 맞추고, 주기마다 모두를 맞춘다. 알림이 풀리고 이슈도 닫힌 포스트는 더 따라가지 않는다. GitHub이 받지 않으면 다음 주기에 다시 한다.

## Considered Options

- **GitHub 앱(봇 이름)으로 열기**: 이슈가 사람에게 묶이지 않는다. 앱 등록과 키 관리가 필요하고 ADR-0025가 2단계에서 미뤘다. 웹훅도 함께 얻으므로, 요청 한도가 걱정될 때 같이 옮긴다.
- **웹훅으로 댓글 받기**: 주기 읽기보다 빠르고 요청이 적다. 서버가 GitHub에서 닿는 주소를 가져야 하고, 레포 웹훅은 관리자 권한이 필요하다. 지금은 결정 PR처럼 주기마다 읽는다.
- **이슈를 닫으면 알림도 풀기**: 알림은 두 작업의 코드에서 계산한 것이라 사람이 지울 수 없다. 포럼에서만 풀림으로 보인다.

## Consequences

- 계약의 `Post`에 `issue`(번호, 주소, 제목, 라벨, 열림)가 붙고, 글 메시지에 `github`(들어온 댓글)가 붙는다. `CONTRACT_VERSION`이 27로 오른다.
- 이슈마다 주기에 GitHub 요청이 둘(이슈, 댓글) 든다. 댓글은 처음 100개만 읽는다.
- 라벨은 push 권한이 있는 토큰일 때만 붙는다(멤버는 push 권한이 있다, ADR-0011). 레포에 없는 라벨 이름을 주었을 때 GitHub이 라벨을 만드는지는 실제 레포에서 확인하지 않았다. 라벨이 빠지면 포럼의 태그에 종류가 안 보이고 카드의 종류 배지만 남는다.
- 이슈를 연 멤버가 레포 권한을 잃어도 이슈는 남는다. 읽기와 닫기는 그때 세션이 있는 다른 멤버의 토큰으로 한다.
- 이미 쌓인 포스트(이 변경 앞의 DB)도 다음 주기에 이슈가 열리고, 그때까지의 글이 차례로 댓글로 간다. 풀린 포스트는 열지 않는다.
